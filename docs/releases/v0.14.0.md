# foxguard v0.14.0 — persistent terminal review

This minor release adds a persistent review workflow, clearer terminal navigation, and safer editor integration. It also fixes Bash parsing, editor scan cancellation, and hosted scan scheduling.

## Terminal review

- Review marks persist per canonical project and scan mode, including the Diff target. Named filters save search, severity, confidence, review status, sorting, and baseline category without changing repository scan configuration.
- Single and batch triage actions show their exact targets and write scope before confirmation. Checked findings survive filter changes; hidden selections are disclosed in the preview.
- Atomic review storage, revision checks, and explicit recovery prevent silent overwrites between terminals. Completed operations release their locks even when another process inherits a file descriptor. Review storage contains fingerprints and filter settings, not source code.
- Finding, source, and sink locations can be opened in the configured editor. Terminal editors work without a desktop session; missing or broken editor settings produce actionable notices without closing the review UI.
- Scan statistics and baseline categories are separated. Finding locations preserve line and column suffixes when shortened. Opening controls stay visible while detail content scrolls, and shortcuts adapt to search and dialogs.
- Source ranges are highlighted inline rather than adding caret rows. Missing source files retain the saved snippet; secret findings continue to use redacted snippets.
- Launch options use three-row cards with vertically centered labels and selection markers. Short terminals retain compact one-row options.

## Scanner correctness

- Valid Bash read/write redirection, including `exec 7<> fifo`, parses correctly using a bundled, patched Bash grammar. The grammar is included in source packages and isolated from upstream grammar symbols in downstream Rust applications.
- The deliberately malformed migration-readiness YAML fixture is excluded only from directory walks. Explicitly scanning the fixture still reports a parse error; genuine malformed source is not hidden.
- Post-quantum inventory recognizes bare `oqs` imports and `OQS_*` APIs. Separated hybrid spellings are attributed to the hybrid without double-counting their embedded base algorithm, while independent base-algorithm uses still appear.
- Rust attributes are scanned for post-quantum identifiers using language-aware comment handling. Python and shell hash-comment prose stays excluded. These fixes address [#607](https://github.com/0sec-labs/foxguard/issues/607), reported by @ARMeeru.

Rust API callers of `rules::pq::scan` and `rules::pq::pq_ready_findings` must now supply the source `Language`. The CLI finding schema is unchanged.

## Website

- Removed the separate rules catalog, generated website inventory, and per-framework rule counts. Rule source and native verification remain in the repository.
- Installation commands remain copyable without the visible npm helper sentence or success notice. Clipboard errors remain visible, and successful copying is announced to screen readers without adding a layout row.

## Editor and hosted delivery

- The VS Code extension cancels obsolete scans and rejects stale results, avoiding outdated diagnostics after newer work supersedes a scan.
- Hosted GitHub App scheduling distributes queued work fairly across installations.
- Main-branch and release GitHub App images share the same native amd64/arm64 build-and-smoke workflow. Public image tags are assembled from the verified image digests.

## Upgrade

The native finding contract remains `1.0.0`. The tag-driven release publishes standalone binaries, crates.io, npm, native CLI wheels on PyPI, the VS Code extension, and the GitHub App image.

After the corresponding publishing job completes:

```sh
pipx upgrade foxguard
npx foxguard@0.14.0 --version
cargo install foxguard --version 0.14.0 --locked
foxguard tui .
```

PyPI packages install the native CLI, not a Python API. Existing Linux musl standalone binaries remain available separately from the glibc Python wheels. Review exports contain the current scan's results, not only filtered rows. Historical resolved baseline entries remain read-only and do not establish verified remediation.
