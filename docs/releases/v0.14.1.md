# foxguard v0.14.1 — fewer false positives, diff-scoped PR policy

This patch release removes a class of false-positive critical SQL findings, adds a diff-scoped pull request policy, and fixes scanner and parser regressions found since v0.14.0.

## Fewer false positives

- `js/no-sql-injection` no longer flags SQL-shaped template literals whose tag parameterizes every interpolation: Drizzle and postgres.js `sql` tags and Prisma `$queryRaw`. Those bind each `${}` as a parameter and are not concatenation sinks. Untagged template literals passed to a query call are still reported as before. Previously this produced critical findings that blocked every pull request in codebases using these libraries.
- JavaScript analysis distinguishes shell `exec` from SQL execution, so database `execute` calls are no longer treated as command injection and shell execution is no longer treated as SQL.
- Metadata values and fixed request origins are proven constant before they are reported, and credential findings are retained across regex mutations.

## Pull request policy

- A new diff-scoped policy (version `v2`, scope `diff`) judges a pull request by the lines it changes instead of by the whole tree. Repository scope could fail a docs-only pull request for a pre-existing finding it never touched. Version `v1` keeps its documented behavior; `v2` is opt-in through the policy file.
- When a blocking finding cannot be shown as a check annotation because it is outside the changed lines, the check now lists it instead of reporting "first 0 as check annotations".

## Scanner and parser correctness

- C, Bash and TypeScript source coverage that had been skipped is restored.
- Parsed syntax trees are no longer retained beyond each analysis pass, which bounds memory on large scans.

## Maintenance

- Release and wheel handoff artifacts now expire after one day.
- Documentation links point at the current 0security locations.

## Upgrade

The native finding contract remains `1.0.0`. The tag-driven release publishes standalone binaries, crates.io, npm, native CLI wheels on PyPI, the VS Code extension and the GitHub App image.

After the corresponding publishing job completes:

```sh
pipx upgrade foxguard
npx foxguard@0.14.1 --version
cargo install foxguard --version 0.14.1 --locked
```

Repositories that rely on `v2` policy files or on the parameterized-SQL-tag behavior need this version or later.
