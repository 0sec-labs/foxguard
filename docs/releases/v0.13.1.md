# foxguard v0.13.1 — native CLI wheels on PyPI

Foxguard can now be distributed through Python package managers without compiling Rust or downloading a binary at runtime.

## Python distribution

- Native CLI wheels for Linux glibc 2.28+ (x86_64 and aarch64), macOS (x86_64 and aarch64), and Windows x86_64.
- Python 3.9+ support. The package installs the `foxguard` executable; it does not expose a Python API or include the MCP, adapter, or GitHub App servers.
- Package versions derive from Cargo metadata. Each platform installs its wheel and exercises version reporting, vulnerable-code detection, and clean scans before release.
- PyPI uploads use GitHub Actions OIDC trusted publishing, restricted to the `pypi` environment and release tags. The Release workflow is now `.github/workflows/workflow.yml`, matching the registered publisher.
- Source distributions and Alpine/musl wheels are not included. Existing standalone Linux musl binaries remain available on GitHub Releases.

After the PyPI publishing job completes:

```sh
pipx install foxguard==0.13.1
foxguard --version
foxguard .
```

In a Python virtual environment, `python -m pip install foxguard==0.13.1` also installs the CLI.

## Hosted GitHub App fixes

- Reconcile installations against all pages of the GitHub API at startup and hourly, preserving existing state on refresh failures and newer webhook updates during reconciliation.
- Classify hosted usage as internal, external, or unknown with `FOXGUARD_INTERNAL_ACCOUNTS`, and include scan correlation fields in structured logs.
- Count evaluated findings in durable pull-request jobs and completion logs.
- Isolate the missing-CodeQL-CLI test from parallel tests instead of mutating their shared process search path.

The native finding contract remains `1.0.0`. Existing npm, crates.io, GitHub Action, VS Code, and GitHub App image publishing remain in the tag-driven release workflow.
