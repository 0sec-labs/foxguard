# foxguard v0.14.2 — non-ASCII paths, bounded subprocess output, safer Windows spawn

This patch release fixes changed-file scanning for non-ASCII file names and hardens subprocess handling.

## Fixes

- Changed-path discovery reads git output NUL-separated, so files with non-ASCII names are no longer quoted and skipped in `--changed` and `diff` scans.
- Coccinelle subprocess output is read through a bounded buffer instead of being collected without a size limit.
- The VS Code extension rejects `cmd.exe` metacharacters in file-name arguments and quotes the rest when it spawns through the Windows shell, so attacker-controlled file names cannot inject commands.

## Maintenance

- The website builds with Astro 7.4.7; CI and `.nvmrc` now use Node 22.23.4 or newer.
- Website dependency updates: undici, vite, smol-toml, sharp and zod.

## Upgrade

The native finding contract remains `1.0.0`.

After the corresponding publishing job completes:

```sh
pipx upgrade foxguard
npx foxguard@0.14.2 --version
cargo install foxguard --version 0.14.2 --locked
```
