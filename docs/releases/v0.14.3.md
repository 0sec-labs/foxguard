# foxguard v0.14.3 — much faster Java scans, fewer Java false positives, Groovy

This release makes large Java scans several times faster, cuts Java false positives, and adds Groovy, Gradle and Jenkinsfile scanning.

## Performance

- Multi-hop (cross-file) analysis now runs in parallel for Java, Python, JavaScript/TypeScript, Go, Ruby, PHP, C# and Kotlin, and only recomposes files whose dependencies changed. A 1.3M-line Java project that took about 68 s now takes about 17 s on a 10-core laptop; output is byte-identical.
- Java and C# expression taint no longer recurses exponentially on long call chains (a 40-call chain is now instant).
- `FOXGUARD_TIMING=1` prints per-phase timings to stderr.
- Known limit: repositories with thousands of files in one Java package still spend most of their time in the compose phase.

## Fewer false positives (Java)

- Pure-literal SQL concatenation is no longer flagged, `execute()` counts as a sink only with a JDBC shape, and property keys, environment-variable names and `${placeholder}` references are not reported as hardcoded secrets.
- A new flow-sensitive check skips XSS, command-injection and SQL sinks whose argument is provably constant or encoded (constant conditions, ternaries and `switch`, reassignment, constant list/map reads, same-file helpers). `PrintWriter.format`/`printf` are XSS sinks when a dynamic argument is not proven safe.
- On the synthetic OWASP Benchmark the deterministic layer's false-positive rate went from 14.4% to 3.9% and its precision from 53.6% to 85.7%. These are internal regression signals for a synthetic benchmark, not an accuracy claim for real code.

## New

- Groovy, Gradle (`.gradle`) and Jenkinsfile scanning with four rules: hardcoded secrets, command injection, unsafe script evaluation, and unsafe interpolation in Jenkins `sh`/`bat` steps.
- Findings are deduplicated across the pattern and taint engines by path, line and CWE in SARIF output. `--production-only` skips test, generated and vendored paths and `--taint-only` keeps taint findings.
- `--file-timeout <secs>` and `--on-file-timeout fail|warn` bound per-file analysis time; timed-out files are reported, never silently dropped.
- Baselines gain a line-insensitive `stable_fingerprint` so unrelated edits no longer make old findings look new. Existing baselines keep working; re-run `foxguard baseline` to add the new fingerprints.
- `benchmarks/precision/owasp_java.py --sarif <file>` scores any scanner's SARIF on the OWASP Benchmark ground truth.

## Fixes

- Autofix: quoted SQL placeholders are unquoted, a missing `execFile`/`execFileSync` import is added, and the `shell=True` fix keeps the callee and its other arguments.
- The GitHub App container image now publishes a multi-arch (amd64 and arm64) manifest from the registry digests.

## Upgrade

The native finding contract remains `1.0.0`.

After the corresponding publishing job completes:

```sh
pipx upgrade foxguard
npx foxguard@0.14.3 --version
cargo install foxguard --version 0.14.3 --locked
```
